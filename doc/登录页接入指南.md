# 登录页接入指南

日期：2026-09-22。适用版本：0.0.1。

## 1. 当前交付范围

这是一个独立 HTML 登录页，包含单密钥输入、刻印入场与点亮、五次错误裂损反馈、明暗主题背景及移动端布局。当前不含认证后端、会话存储、业务首页、调试按钮或默认密码。

业务接入集中在 `login-adapter.js`。动画模块不判断密钥是否正确，也不指定业务目的地。默认 `authenticate` 和 `onAuthenticated` 均为 `null`：非空提交提示“登录服务尚未接入”，不会当作成功，也不计入错误次数。空值仍沿用已有的错误反馈。

## 2. 迁移哪些文件

将下列文件按当前相对目录复制到宿主项目的一个静态目录，例如 `public/login/`：

```text
login/
├── index.html
├── theme.js
├── login.css
├── backgrounds.css
├── login.js
├── login-adapter.js
├── token-input.js
├── signet.js
├── signet-fracture.js
├── signet-cracks.js
├── background-particles.js
└── assets/
    ├── images/elysia-signet-solid.png
    └── fonts/
        ├── README.md
        └── Italianno-OFL.txt
```

刻印只加载 `elysia-signet-solid.png`；旧线稿 `elysia-signet.png` 不参与运行。底部字标已转为 `index.html` 内联 SVG，无须请求外部字体，但迁移时保留字体来源和许可证。`素材/`、`.codegraph/`、设计对比页和历史参考资料不需要部署。临时业务页及其专用 `styles.css` 已删除。

现有 Node 服务不是运行时依赖。部署到宿主静态资源服务后不需要复制 `server.js` 和 `package.json`；它们仅支持本仓库执行 `npm start`，在 `127.0.0.1:11451` 本地预览。

## 3. 页面路径与加载顺序

- 使用 HTTP(S) 访问；不要直接双击 `index.html` 以 `file://` 打开模块脚本。
- 静态目录挂载在 `/login/` 时，入口使用 `/login/` 或 `/login/index.html`。将不带末尾斜线的 `/login` 重定向到 `/login/`，避免 HTML 中相对资源地址落到错误目录。
- `theme.js` 必须保留为 `<head>` 中位于样式表之前的普通脚本，不加 `async`、`defer` 或 `type="module"`。它先确定浏览器主题，防止暗色首屏闪出亮色背景。
- `login.js` 保持 `type="module"`，导入路径基于模块本身。刻印图片也通过 `import.meta.url` 相对于 `signet.js` 定位；更改资源目录时同时更新 `index.html` 的图片预加载地址。
- JS 和 CSS 返回正确的 MIME 类型，资源路由不要被宿主的 SPA HTML 回退覆盖。尤其确认新文件 `theme.js`、`login-adapter.js` 可以直接请求。
- 有 CSP 的项目需要允许本目录脚本、样式和图片；页面还使用内联 SVG、`style` 动画变量及 JS 设置样式。应按宿主策略适配这些用法，不能只禁用内联样式后期待原动画保持不变。

## 4. 认证适配契约

编辑 `login-adapter.js` 导出的 `loginAdapter` 对象：

| 字段 | 契约 | 默认行为 |
| --- | --- | --- |
| `authenticate(token, { signal })` | 异步或同步返回带布尔值 `authenticated` 的对象 | `null`，提示登录服务未接入 |
| `onAuthenticated(result)` | 成功动画与退场完成后调用，可返回 Promise；负责跳转或移除登录页 | `null`，完整点亮后留在原页 |

`token` 是输入框的原始字符串，不自动 `trim`，也不改变大小写。空字符串由页面直接处理，不调用认证适配器；空格字符串仍原样传递，由后端决定是否有效。`signal` 是本次请求的 `AbortSignal`，应传递给 `fetch` 或宿主请求客户端，离开页面或恢复初始流程时会取消请求。

认证返回值约定如下：

```js
// 只有后端已经确认成功，才返回 true。
{ authenticated: true, user: { id: '用户标识' } }

// 只有明确的密钥无效才返回 false；会累积裂损和错误次数。
{ authenticated: false }

// 网络异常、超时、限流、服务不可用、解析异常等，应抛出异常。
// 页面显示通用服务提示，保留输入、当前计数和裂损，不扣次数。
throw new Error('authentication service unavailable');
```

页面要求 `authenticated` 为真正的布尔值。空结果、字符串 `"true"`、缺少该字段等会作为适配异常处理，不放行、不扣次数。其他业务字段原样传给 `onAuthenticated`；界面不解析、不打印、不持久化这些数据，也不会直接显示后端异常内容。

### 一个完整的适配示例

以下接口路径、请求字段、响应结构和目的地仅用于说明映射方式，**不是本仓库已经实现的后端协议**。示例假定宿主提供 `POST /api/login`，接收 `{ token }`，错误密钥返回 401，成功返回 `{ user }` 并建立 Cookie 会话；业务入口为 `/app/`。接入时按实际服务约定替换。

```js
// login-adapter.js
export const loginAdapter = {
  async authenticate(token, { signal }) {
    const response = await fetch('/api/login', {
      method: 'POST',
      credentials: 'same-origin',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ token }),
      signal,
    });

    if (response.status === 401) return { authenticated: false };
    if (!response.ok) throw new Error('authentication service unavailable');

    const data = await response.json();
    return { authenticated: true, user: data.user };
  },

  onAuthenticated(result) {
    // 此时刻印已完全亮起并退场，会话已由认证接口建立。
    window.location.replace('/app/');
  },
};
```

如果服务返回 204 或成功标记在 JSON 中，应在适配器转换；不要照搬 `response.json()` 或把所有 HTTP 错误都转换成错误密钥。页面不规定请求超时时长，使用宿主现有请求客户端的超时策略，同时保留传入的取消信号。跨域时按实际会话方式配置请求凭据和服务端 CORS，不能直接照搬同源示例。

## 5. 提交流程与状态边界

1. 底部字标及横线完成 → 刻印让位 → 输入框展开 → 开始背景粒子运动并允许输入。
2. 非空提交调用认证适配器。等待期间输入只读，保留焦点和内容；表单设置 `aria-busy`，并阻止重复请求。此时不会提前收起输入框或点亮。
3. 返回 `authenticated: false`：输入恢复可编辑，触发整体抖动、次数条和裂损，前四次没有错误文字。第五次立即锁定，完整破碎后展开“错误次数过多，请稍后刷新重试”，保留漂浮碎片。
4. 抛出异常：显示“暂时无法验证密钥，请稍后重试”，恢复编辑；不增加次数、不触发新的裂损。用户编辑后清除提示。
5. 返回 `authenticated: true`：清除密钥并禁用输入，刻印从当前相位转向亮度峰值，与“欢迎回来”、收起和归中并行；随后点亮，并同步修复裂损。
6. 如果配置 `onAuthenticated`，完整点亮保持 360ms，整体淡出 360ms，再调用一次完成回调。减少动态效果时跳过这段退场等待，仍等刻印完成。回调负责导航或卸载登录页；不要只返回而留着已经淡出的页面。
7. 未配置完成回调时，不执行退场，停留在居中的完整刻印。回调抛出异常时恢复刻印可见，并提示“登录已验证，但无法进入页面，请刷新重试”；不会将已经通过的认证计为密钥错误，也不会自动重复执行回调。

前四次裂损生长不阻止下一次主动提交，连续错误从当前损伤接续；长按 Enter 不重复提交。第五次后必须刷新页面重新开始，左上角已没有调试重置按钮。

浏览器离开页面时会中止认证请求，并用流程编号忽略旧响应，避免旧请求在恢复后点亮或跳转。浏览器从往返缓存恢复页面时会清空输入、次数和损伤并重新进入登录流程；普通刷新会重新播放所有入场内容，包括字标。动画期间单纯切换浏览器标签页不取消认证。

五次计数是本页面的视觉状态，刷新后清零，不是服务端限流。真实鉴权、权限校验、会话有效期、封禁/重试规则仍由宿主后端负责；前端动画和 `authenticated` 字段不能代替这些判断。成功会话应在认证阶段建立，完成回调只负责进入宿主界面。

## 6. 主题策略

- 首次加载同步读取 `prefers-color-scheme: dark`；未手动点击时持续监听浏览器偏好变化。
- 点击右上角按钮后，本次页面使用手动选择，后续浏览器主题变化不覆盖它。
- 不读写 `localStorage` 或 Cookie 保存偏好；刷新后重新跟随浏览器。往返缓存恢复保留该页面内的手动选择。
- 主题变化通过内部事件 `login-theme-change` 刷新刻印和背景颜色，不清空输入、次数或损伤，也不重播入场。
- 明亮主题使用晨雾花庭与下落花瓣；暗色使用上行萤火。后台暂停动态效果，尊重浏览器的减少动态效果设置。

宿主如果已有全站主题状态，应统一修改 `theme.js` 的主题来源，避免宿主与本页同时写 `data-theme`。修改数据属性后也要通知刻印与背景更新，不能只替换 CSS 颜色。

## 7. 接入框架项目时的边界

最直接的方式是把这些文件作为独立登录文档提供，由登录成功回调导航到 React、Vue 或其他宿主应用。这样现有全局 CSS、固定 ID、Canvas 生命周期与宿主界面互不混用。

当前实现按“一个文档、一份登录页”初始化，**不是可重复挂载的框架组件**。不要直接反复执行 `login.js` 或把整页 HTML 多次插入同一 SPA 文档：模块包含 document/window 事件、ResizeObserver、CSS/元素动画和 Canvas 帧循环，尚未提供统一的 `mount`/`destroy` 接口。

如需将其转换为 SPA 路由组件，应在宿主改造中为 DOM 查询增加组件根节点，把全局样式限定到组件范围，并在卸载时取消请求、帧循环和元素动画、移除事件监听、断开 ResizeObserver。背景与刻印的遮挡目标也应改为组件内元素。SSR 时在客户端挂载后初始化这些浏览器 API；`theme.js` 的首屏策略需配合宿主文档入口。

不建议仅将当前完成回调改为客户端路由切换，却保留整套全局监听和持续帧循环；当前独立页面方式会随文档离开自然销毁这些资源。

## 8. 常用配置位置

| 调整项 | 文件与位置 | 当前值 |
| --- | --- | --- |
| 桌面刻印、输入框宽度 | `login.css` 的 `.login-scene` | `--signet-width: 400px`、`--input-width: 360px` |
| 移动端输入框宽度 | `login.css` 的 `max-width: 768px` 媒体查询 | `--input-width: 300px` |
| 移动端排列 | 同一媒体查询的 `.login-scene`、`.signet` | 刻印在上、输入框在下，组合居中 |
| 浮动与呼吸周期 | `login.js` 的 `IDLE_PERIOD` | 5500ms，同周期、同相位 |
| 刻印点亮时长 | `signet.js` 的 `LIGHT_DURATION` | 2000ms，不包含欢迎与归中 |
| 裂损、第五次破碎时长 | `signet.js` 的 `FRACTURE_DURATION`、`SHATTER_DURATION` | 1200ms、1700ms |
| 输入提示打字间隔 | `token-input.js` 的 `HINT_INTERVAL` | 110ms |
| 背景数量、速度、寿命、遮挡 | `background-particles.js` 顶部常量 | 亮色花瓣、暗色萤火分别配置 |
| 晨雾颜色与周期 | `backgrounds.css` | 三层薄雾 |
| 主题基础色与输入框细节 | `login.css` 的 `:root` 和暗色覆盖 | 紫色／粉色主题 |

五次错误与三条主裂痕、四阶段裂损、五格 DOM 绑定，不是只改 `MAX_FAILURES` 就能任意更改上限；如果宿主要求另一套次数规则，需要同时调整 `index.html` 的次数条、ARIA 属性及裂损模块的阶段映射。

更多刻印参数见 [刻印点亮算法](刻印点亮算法.md)，外观共识见 [爱莉希雅主题登录页设计共识](爱莉希雅主题登录页设计共识.md)。

## 9. 接入后的核对项

核对真实认证成功、错误密钥、网络中断及服务限流的结果映射；确认只有成功认证且动画完成才导航。检查一次请求尚未完成时再次按 Enter 不会重复请求，错误累计第五次锁定，普通服务异常不扣次数。

在宿主实际部署路径核对所有资源返回 200，特别是 `theme.js`、适配器模块和刻印图片；确认已删除的 `/dashboard.html` 不再被当作登录目的地。验证初始暗色、浏览器主题实时切换、手动主题优先、刷新恢复跟随，以及窄屏布局和减少动态效果。

本仓库的本地验证不包含宿主认证接口、真实会话、业务路由、跨域或 CSP 部署验收，这些需要在实际接入项目中完成。
