# 刻印点亮算法

日期：2026-09-21。状态：当前试制实现，待视觉反馈。

## 问题与目标

上一版将骨架拆成独立短线段分别绘制，局部出现断点、圆头和色块；最终又淡入完整实心图片，导致流动过程与完成状态脱节。本版移除这些路径及叠加层，让同一批像素从线稿连续变成最终实心形状。

## 传播时间场

1. 从用户提供的实心 PNG 提取覆盖率：`alpha = min(1, green / 240) × sourceAlpha`。此值用于识别传播笔画及生成未点亮轮廓，不替代原图最终覆盖率。洋红色半透明区域是素材自带泛光，不能当作背景删除；渲染保留其原始 RGB 和透明度。
2. 在 192 × 192 网格内计算笔画到边界的距离。内部阻力为 `1 + 2 / (distance + 1)`，笔画中心较快、边缘稍慢；空隙阻力为 18。
3. 从最靠近花心的内部像素出发，用八邻域 Dijkstra 计算每个位置的最早到达时间。各分支共享同一个时间场，不再各自启动短动画。
4. 空隙承担连接不相交片段的时间代价，不额外生成连线；实际显示区域由原图实心和自带泛光的透明度共同决定。
5. 将到达时间归一化到 `[0, 0.78]`，双线性插值到 640 × 640 渲染画布。低分辨率只用于求解传播，轮廓与抗锯齿仍由较高分辨率的原图采样决定。

这是一种用于视觉设计的加权距离传播模型，不是物理流体模拟。它使光沿笔画传播、自然分叉，并避免随机噪声和跳闪。

## 未点亮轮廓

不再加载独立透明线稿。对动画使用的 640 × 640 实心覆盖率，以半径 2px 的圆形邻域取最小值，得到向内收缩的覆盖率；用原覆盖率减去收缩结果，生成完全位于点亮笔画内部的细轮廓。覆盖率保持连续值以保留抗锯齿。

未点亮轮廓与点亮笔画共用采样坐标和到达时间，光流到达时在原位置充盈，轮廓同步消退。该处理仅在初始化时执行，不修改完成帧及原生泛光。

## 待机轮廓自发光

主体轮廓颜色及透明度保持固定。将同一轮廓绘入独立画布，使用 1.5px 模糊及 4px 同色扩散形成柔光，每 5.5 秒平滑增强再减弱。两个画布放在同一浮动容器内，始终对齐，以 5.5 秒周期平滑上下浮动，总位移为 7px。位移与柔光同帧启动，共用周期及分段缓动，上升时增强、下降时减弱，最高点最亮、最低点最暗。待机时柔光画布仅在初始化及主题切换时更新，由元素位移和柔光层透明度驱动，不逐帧重绘。进入点亮后，其覆盖率随各处笔画的充盈逐帧更新。

用户提交时，立即把当前周期转为向峰值上升：上升段保持当前进度；下降段按对称缓动镜像到同亮度、同位置的上升段。随后单向升至峰值并保持，上升与输入框收起、刻印归中同时进行。归中及达峰均完成后直接点亮，不把位移归零、不整体淡出柔光，也不重置渲染画面。

点亮时刻印保持峰值位置（-7px），柔光图层保持峰值不透明度；每个轮廓像素的柔光覆盖率按 `line × (1 - settled)` 随该处笔画稳定逐步退去，尚未充盈的轮廓保留原亮度，原生泛光连续接替。最终柔光覆盖率归零，只显示原图自带泛光。后台暂停，减少动态效果时直接结束上升。

## 登录主体联动

入场先将未点亮刻印置于视口中央，用 500ms 显现，等待底部字体书写及两侧横线全部完成后，再用 720ms 左移到并列布局的位置；移动完成后，输入框从中心向左上、右下展开，900ms 后允许输入。

提交正确演示密钥 `123` 后，输入内容先淡出 100ms，框内用约 500ms 展开“欢迎回来”并完整停留约 600ms，再让文字与两处晶棱在 360ms 内向输入框中心合拢消失；随后刻印用 720ms 回到视口中央，等待从提交瞬间开始的单向上升达到峰值，再开始 1800ms 点亮。以当前周期相位 t 计算上升段时间 `min(t, 5500 - t)`，新有限动画采用原有 ease-in-out 曲线，持续到 2750ms 并保持终态；例如下降段亮度 0.5 会直接转为从 0.5 上升到 1，不先下降或重置。上升最多需要半周期 2750ms，与欢迎文字、收起及归中并行；减少动态效果时静态展示欢迎文字 650ms，跳过上升等待。各段等待实际动画完成，不依靠独立计时器猜测顺序。居中位移根据容器与刻印宽度计算，窄屏与窗口调整保持相同布局规则。

调试按钮共用这一流程，完成后保留居中的完整刻印且不跳转；可再次预览点亮，重置则重新加载整页，包括字标与输入框动画。浏览器后退恢复会取消旧流程并重新入场。减少动态效果时省略位移等待，保留相同状态顺序。

## 连续充盈与收尾

每个像素的局部时间为 `age = progress - arrival`。

- `smoothstep(0, 0.12, age)` 控制充盈度，同时逐渐消退该位置的旧线稿。
- 前锋处叠加一次窄而柔和的亮度波，表现光在流动；经过后保留稳定亮色。
- `smoothstep(0.025, 0.21, age)` 将笔画流动粉色逐渐稳定为各像素原始 RGB，主要实心色为 `#FEF0FE`；泛光直接使用原图颜色，不套用主题粉色。
- 当全局进度达到 1，所有像素的局部时间至少为 0.22，充盈度和颜色均自然到达最终值。不存在最后一帧替换图片、突然填满或额外淡入层。

单次传播持续 1800ms，整体进度使用 `p = t × (2 - t)`：起始具有非零推进速度，末端速度平滑降至零，避免全局缓起与逐像素充盈缓起叠加造成视觉停顿。保留每个像素原有的平滑充盈、颜色稳定与泛光扩散；不跳过初始状态，不改变终态。完整状态停留 360ms，再用 360ms 淡出。登录跳转等待渲染器实际完成最后一帧和退场动画，无状态说明文字。

## 填色与泛光核对

2026-09-21 经用户指出并复核，原图半透明洋红区域是自带泛光，早先将其视为底色删除、再用 CSS 重建泛光的做法不正确。

当前完整采样原图 RGB 和透明度，点亮终态不叠加额外的 CSS 阴影与背景光晕。按最新反馈，泛光恢复原生 100% 强度，不再乘以 0.65。完成状态的颜色和透明度均与对齐采样后的原图一致。

画布在原 640 坐标系四周各预留 112 单位（17.5%），完整绘制原 PNG，避免裁切原生光晕；主体大小与布局保持一致。

## 泛光随笔画亮度扩散

旧版对实心与泛光使用同一个到达时间场。外围区域的时间被封顶为 0.78，导致许多泛光像素同时启动，产生生硬的光圈变化。现将两者分开：

1. 每帧只将实心笔画视为光源，局部亮度为 `E = coreAlpha × smoothstep(0.015, 0.20, progress - arrival)`，比笔画本身的充盈稍缓。
2. 在 192 × 192 网格上用四个方向的指数扩散计算邻近笔画的亮度贡献，扩散尺度为 7 个网格像素。扩散核没有截断半径，避免外围出现硬边。
3. 将当前扩散结果除以完整点亮时的扩散结果，得到局部泛光响应 `H = diffuse(E) / diffuse(coreAlpha)`。它跟随周围已亮笔画连续增长，不再取决于空隙的传播到达时间。
4. 最终透明度为 `coreAlpha × charge + (sourceAlpha - coreAlpha) × H`。颜色仍来自原图，扩散只控制原生泛光的显现程度，不生成新的光晕颜色或轮廓。
5. 完全点亮时两次扩散输入相同，`H` 自然等于 1，因此平滑恢复原图完整泛光，不需要结尾补亮或切换图层。

逐帧检查确认采样泛光亮度没有回落；完成帧与对齐采样原图的透明度及预乘颜色一致。

## 运行与维护

- `signet.js` 负责资源采样、一次性传播场求解和 Canvas 绘制；`login.js` 负责登录流程与页面跳转。
- 只遍历原图有效像素。初始化后不再求解路径；仅登录点亮期间申请动画帧，静止时不持续重绘。
- 切换主题更新线稿和流动颜色，不重算时间场，也不重播。最终仍采用原图浅粉白。
- 页面恢复时限制单帧时间步长，避免后台时间直接跳过整段点亮；减少动态效果模式直接绘制完整终态。
- 重新登录与浏览器后退恢复初始状态；取消未完成渲染会阻止旧流程继续跳转。`play()` 从当前进度继续渲染，只有显式 `reset()` 才清零；调试完整重播与页面恢复使用显式重置。
- 画布分辨率、阻力、前锋宽度、稳定时长为试制参数，可按实际观感调整。改变原图时应同步检查图案对齐、实心与泛光分离参数和花心位置。
